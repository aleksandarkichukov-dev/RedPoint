## 1 · Контекст

Red Point Варна — 3 физически магазина, мъжки спортно-елегантни дрехи. Текущият сайт [red-point.bg](https://red-point.bg/) е самописен Laravel върху **PHP 5.5** зад Cloudflare, отпреди ~10 години.

Строим пълна подмяна:

- **Начална страница** в духа на [unrulyagency.com](https://www.unrulyagency.com/home) — кинематографична, редакционна, hero видео, категориен карусел
- **Продуктови страници** в духа на [g-star.com](https://www.g-star.com/en_bg) — плоски, правоъгълни, индустриални, дисциплинирани
- **Картово плащане** (myPOS) + наложен платеж
- **Спиди / Еконт** модул
- **Система за качване/сваляне на продукти**, която клиентът ползва сам всеки ден
- **Чатбот без LLM** за базова продуктова информация

Ключова разлика от типичен e-commerce проект: **клиентът не е технически човек и ще управлява каталога сам.** Bulk модулът (Фаза 7) не е второстепенен — той е основният ежедневен интерфейс на клиента и заслужава същото UX внимание като началната страница.

## 2 · Заключени решения

| Тема | Решение |
|---|---|
| Frontend | Next.js 15, App Router, RSC, Tailwind v4 |
| Backend | **Medusa v2** (Node + PostgreSQL + Redis) |
| Плащане | **myPOS Checkout** + наложен платеж (COD) |
| Куриери | Спиди + Еконт |
| Данни | Seed 20–30 артикула на категория; клиентът добавя останалото сам |
| Езици | BG + EN (RO отпада засега) |
| Валута | **EUR основна**, BGN в скоби, фиксиран курс 1.95583 |
| Admin | Стандартен Medusa admin + собствен BG модул за bulk import/export |
| Чатбот | Rule-based, без LLM |
| Видео | Генерира се с Higgsfield |
| Хостинг | SuperHosting.bg — **Managed VPS**, не споделен план |

**Защо Medusa, а не Shopify/Woo:** Shopify не поддържа български виртуален ПОС. WooCommerce няма да даде исканата динамика без сериозна борба. Medusa дава наготово продукти с варианти, склад, кошница, поръчки, admin и plugin система — точно там влизат myPOS и Спиди/Еконт.

**Защо Managed VPS, а не споделен хостинг:** SuperHosting поддържат Node.js, PostgreSQL и Redis ([потвърдено](https://help.superhosting.bg/node-js.html)), но на споделен план Node върви през Passenger, който убива дълготрайни процеси. Medusa worker-ът трябва да живее постоянно. **Уточни това с клиента преди да купи хостинг** — иначе се плаща два пъти.

## 4 · Скилове — кой, кога, защо

### `SKILL.md` в корена на репото — **задължителен винаги**

Това е дизайн системата (g-star-design-system), извлечена от живите computed styles на g-star.com. Прочети я преди първата линия CSS. Няколко правила от нея, които са безусловни:

1. **Нула заоблени ъгли.** Всичко е правоъгълно (0–1px). Това е най-идентичната черта — един `border-radius: 8px` и сайтът моментално изглежда off-brand.
2. **Нула сенки.** Дълбочината идва от плоски цветни блокове (`#E4E6E7` зад продуктовите снимки), не от blur.
3. **`#C2311E` само за разпродажба/намаление.** Никъде другаде. Червеното носи тежест точно защото е рядко.
4. **Заглавия uppercase condensed, бутони lowercase.** Това е нарочен ритъм, не непоследователност.
5. Без градиенти, без glassmorphism, без вторични брандови цветове.

> ⚠️ **Първа задача:** SKILL.md реферира `assets/tokens.css`, който **липсва** в папката. Трябва да го създадеш от таблицата с цветове в самия файл. Също: инсталирай SKILL.md като истински скил в `.claude/skills/g-star-design-system/`, за да се зарежда автоматично, вместо да разчиташ да си го спомниш.

### Извличане на данни — конкретни селектори

**Основни полета — от JSON-LD.** Всяка продуктова страница има валиден `<script type="application/ld+json">` с `@type: "Product"`:
```json
{
  "name": "Мъжка бяла тениска с декорация 15786",
  "image": "https://red-point.bg/images/color_pictures/20640/15373_1717072116_502x616.jpg",
  "description": "100%памук",
  "sku": "15786",
  "offers": { "price": "16.00", "priceCurrency": "BGN", "availability": "...InStock" }
}
```

> ⚠️ **Цената в JSON-LD е ненадеждна.** Видях `16.00` при реално показана `62.59` — вероятно базова/остаряла стойност. Вземай **рендираната цена от DOM** и логвай разминаванията в отделен отчет за преглед от клиента.

**Останалото — от DOM:**

| Данни | Селектор / шаблон |
|---|---|
| Размери | `ul#sizes_list li` · атрибут `data-size-id` |
| Изчерпан размер | класове `cross no_size_quantity` (title: „Изчерпано количество") |
| Цветове | елементи с `data-color-id` · `.small_product_color_pictures` |
| Снимки | `/images/color_pictures/{color_id}/{product_id}_{ts}_{res}.jpg` |
| Резолюции | `99x98` (thumb) · `502x616` (medium) · `2000h` (оригинал — **тегли този**) |
| Таблица с размери | `table.sizes_table_with_pic` — колони: Размер, A (ширина см), B (дължина см) |
| Състав | JSON-LD `description` (напр. „100%памук") |
| Артикулен № | JSON-LD `sku` — съвпада с числото в края на името |

**Модел на данните:** `продукт → цвят → набор снимки → размери с наличност`. Снимките са **per-цвят**, не per-продукт. Това определя как се строят вариантите.

**Таблицата с размери в сантиметри е измерена от служители на магазина** и е реална за конкретния продукт. Това е рядкост в български e-commerce и е конкурентно предимство — мигрира се задължително и се показва добре на PDP.

### Cloudflare
Блокира след ~10 бързи заявки. Скрейпърът иска Playwright (не plain `fetch`), throttle **1.5–2 s между заявките**, resumable on-disk cache, за да не започваш отначало при блокиране.

```
d:\redpoint\
├─ apps\
│  ├─ storefront\           Next.js 15 · App Router · Tailwind v4
│  └─ backend\              Medusa v2
│     └─ src\
│        ├─ modules\        payment-mypos, fulfillment-speedy, fulfillment-econt

│        └─ api\            chatbot endpoints
├─ packages\

├─ tools\
│  └─ scraper\              Playwright, еднократен seed
├─ seed\                    products.json + изтеглени снимки
├─ SKILL.md                 дизайн системата — не се пипа
└─ docker-compose.yml       postgres + redis + backend + storefront
```

Всичко Docker-базирано и конфигурирано през env променливи — хостингът се решава късно, кодът трябва да е portable.

### Мапинг Red Point → Medusa v2

| Red Point | Medusa |
|---|---|
| Продукт | `Product`, `handle` = slug |
| Артикулен № (17497) | `variant.sku` + `product.external_id` |
| Цвят | `ProductOption` „Цвят" |
| Размер | `ProductOption` „Размер" |
| Цвят × Размер | `ProductVariant` + `InventoryItem` |
| Снимки per цвят | `product.images` + `product.metadata.color_images: { "Сив": [id, ...] }` |
| Таблица с размери | `product.metadata.size_chart: [{ size, a_cm, b_cm }]` |
| Състав | `product.material` |
| Категории | `ProductCategory` — запазва се йерархията от раздел 5 |

**Внимание:** Medusa v2 **няма** per-variant галерия. Затова снимките се държат на ниво продукт, а `metadata.color_images` е картата кой цвят кои снимки показва. Storefront-ът сменя галерията от тази карта при избор на цвят.

**Цени:** `EUR` е store currency. BGN се **изчислява** при рендиране (× 1.95583, закръгление нагоре до стотинка). Не поддържай втора ценова листа — гарантиран разсинхрон.

## 7 · Фази

### Фаза 0 · Основа

**Цел:** проектът да е готов за писане на UI, който не може да излезе от дизайн системата.

1. Monorepo (pnpm workspaces), Docker Compose с postgres + redis
2. Създай `packages/design-system/tokens.css` от таблицата с цветове в SKILL.md
3. Конфигурирай Tailwind v4 **изцяло от токените** — изтрий дефолтната скала за радиуси и сенки, за да е физически невъзможно да напишеш `rounded-lg` или `shadow-md`
4. Шрифтове: Barlow Condensed (заглавия), Inter или Gotham fallback (текст). Без monospace никъде.
5. Примитиви: `Button` (3 варианта от SKILL.md), `Badge`, `ProductCard`, `Input`, `FilterBar`
6. Извикай `init` за `CLAUDE.md`

**Извикай:** `design-taste-frontend` — задава посоката преди първия UI код.

**Готово когато:** примитивите са рендирани на демо страница и нито един няма заоблен ъгъл или сянка.

---

### Фаза 1 · Скрейпър

> Прескочи изцяло, ако клиентът даде експорт от базата.

**Цел:** `seed/products.json` + изтеглени снимки.

1. Playwright скрипт в `tools/scraper`
2. Обходи категорийното дърво (раздел 5), вземи **първите 20–30 продукта на категория**
3. Парсвай JSON-LD за име/sku/състав/наличност; **цената от DOM**
4. Парсвай размери, наличности, цветове, см таблица по селекторите от раздел 5
5. Тегли `_2000h` снимките, организирани по `{sku}/{цвят}/{n}.jpg`
6. Throttle 1.5–2 s, resumable кеш на диска
7. Отчет за разминаванията JSON-LD ↔ DOM цена

**Готово когато:** `products.json` минава схема валидация и всеки продукт има ≥1 цвят, ≥1 размер и ≥1 снимка.

### Фаза 2 · Medusa backend

1. Medusa v2 + Postgres + Redis през Docker Compose
2. Категорийно дърво по раздел 5
3. Seed скрипт: `products.json` → Medusa **workflows** (не direct DB writes — заобикалянето на workflows чупи inventory и search индексите)
4. Снимки към S3-съвместимо хранилище или локален диск на VPS-а
5. EUR регион, ДДС ставка, доставни зони

**Готово когато:** `pnpm seed` пълни базата и продуктите се виждат правилно в Medusa admin с всички варианти.

### Фаза 3 · Начална страница

Скелетът е от unruly (кинематографичен, вертикално разказан), дисциплината от g-star (плоско, правоъгълно, монохромно).

**Минавай секциите една по една за одобрение — клиентът иска да ги коментира поотделно.**

**1 · Nav** — залепен, тънък. Лого вляво, категории център, търсене/любими/количка вдясно. Прозрачен върху hero-то, плътно бял при скрол. Mega menu с категорийни снимки при hover.

**2 · Hero** — цял viewport, muted autoplay loop (Higgsfield), контрастен монохромен грейд. Огромен condensed uppercase надпис „щампован" върху видеото. Lowercase ghost бутон (прозрачен фон, 2px бял кант). Mask-reveal на текста при зареждане, дискретен scroll cue.

**3 · Категориен карусел** — хоризонтален drag/scroll с високи портретни плочки: Якета · Дънки · Ризи · Тениски · Панталони · Обувки · Аксесоари. Скрол-обвързано движение, snap при drag.

**4 · Manifesto лента** — трите колони на unruly, преведени: **20 години** във Варна · **3 магазина** · **доставка на следващия ден**. Голяма цифра + къс текст, черен фон.

**5 · Нови постъпления** — 4-up продуктова решетка по спецификацията от Фаза 4.

**6 · Кампанийна лента** — второ full-bleed видео/визуал. Единственото място за `#C2311E`, и то само ако носи разпродажбено съобщение.

**7 · Разпродажба** — рейл с `-%` баджове.

**8 · Магазини** — трите адреса с работно време и карта. Данните са в раздел 5.

**9 · Бюлетин + футър** — черен панел, uppercase, минимален.

**Бюджет за движение:** mask reveal на заглавия, хоризонтален скрол на карусела, crossfade при hover, преход на nav-а. Без параллакс каша. `prefers-reduced-motion` изключва всичко освен opacity.

**Извикай:** `higgsfield-generate` за видеата (Seedance 2.0), после `design-taste-frontend` за композицията, накрая `emil-design-eng` за полиране на движението.

### Фаза 4 · PLP + PDP

**Списък (PLP)** — 4 колони desktop / 2 mobile.

Продуктова карта: снимка на `#E4E6E7` фон · hover сменя към втора снимка · uppercase име · EUR цена получер + BGN в скоби · цветни swatch-ове под цената · wishlist glyph горе вдясно без chrome · `-%` бадж горе вляво само при намаление.

Филтърна лента: **само текст** с chevron (`Категория ▾`, `Размер ▾`, `Цвят ▾`), разделен с `#696969` хеърлайни. **Не** ги прави bordered dropdown бутони — SKILL.md изрично го забранява.

Infinite scroll със синхронизиран `?page=` в URL-а, за да работят share и back бутонът.

**Продукт (PDP)** — залепена галерия вляво (per-цвят, zoom), информация вдясно: име · артикулен № · цена · цветни swatch-ове (сменят галерията) · размери като правоъгълни плочки със задраскани изчерпани · „Виж таблицата с размери" отваря реалната см таблица · състав · доставка. Свързани продукти отдолу.

**Извикай:** `impeccable` срещу готовия код, после `emil-design-eng` за hover/transition детайлите.

### Фаза 5 · Кошница и checkout

Едностраничен checkout: контакти → доставка → плащане.

- **myPOS Checkout** като Medusa payment provider: hosted redirect flow, IPN webhook с **проверка на подписа** (не пропускай това — иначе всеки може да фалшифицира платена поръчка)
- **Наложен платеж** като втори метод
- Имейл потвърждения на BG/EN

**Готово когато:** пълен flow в myPOS sandbox завършва с поръчка в Medusa със статус captured.

### Фаза 6 · Спиди / Еконт

Medusa fulfillment providers.

- **Еконт** — през тяхното delivery widget (iframe избор на офис, връща JSON). Най-бързият път, не пиши свой office picker.
- **Спиди** — [REST API](https://api.speedy.bg/web-api.html) за списък офиси, калкулация на цена, генериране на товарителница от admin-а
- Избор на офис/адрес в checkout-а
- COD сумата се подава на куриера при генериране на товарителницата

### Фаза 7 · BG модул за качване/сваляне

**Това е основният ежедневен инструмент на клиента. Отнеси се към него като към продукт, не като към форма.**

Medusa admin extension route (`src/admin/routes/bulk`), **изцяло на български**:

- Drag-and-drop на `.xlsx` + `.zip` със снимки
- Съответствие на снимките по конвенция `{артикул}_{цвят}_{номер}.jpg`
- **Preview таблица с валидация ред по ред**, с разбираеми грешки на български: „Ред 14: липсва цвят", не „ValidationError: color is required"
- Един бутон „Импортирай" → create/update през Medusa workflows
- **Атомарност:** или минава всичко, или нищо. Частичен импорт оставя клиента в невъзможно състояние.
- Експорт назад в същия `.xlsx` формат — за масова смяна на цени и наличности
- Шаблонен файл за сваляне

**Извикай:** `impeccable` — това е екранът с най-висока цена на UX грешка в целия проект.

### Фаза 8 · Чатбот (без LLM)

Панел долу вдясно по дизайн системата — правоъгълен, черно/бяло, без сянка.

**Нормализация на входа** (най-подценяваната част): малки букви, махане на диакритика, **поддръжка на латиница-транслитерация** — българите пишат „denki" и „teniska" също толкова често, колкото „дънки" и „тениска".

Възможности:

| Интент | Реализация |
|---|---|
| Продукт по артикулен № | Точно съвпадение, мигновено |
| Продукт по име/описание | Trigram/fuzzy индекс над каталога |
| Наличност по размер | Жива справка в Medusa inventory |
| Статус на поръчка | № поръчка + имейл → статус + линк към товарителницата |
| FAQ | Бутонно меню + keyword matching над JSON файл, редактируем от admin-а |
| Магазини | Адреси/часове от данните в раздел 5 |
| Fallback | „Свържи ме с човек" → форма или телефон |

Отговорите за продукти се връщат като карта с цена, налични размери и линк — не като чист текст.

### Фаза 9 · Деплой

1. Docker Compose на SuperHosting **Managed VPS**
2. nginx reverse proxy + Let's Encrypt
3. Автоматични backup-и на Postgres
4. `.env` per среда, нищо чувствително в репото
5. **301 redirect карта** от старите URL-и (`/product/{id}/...`) към новите handle-ове

Точка 5 не е опционална. Домейнът е на 10 години и има натрупан SEO авторитет — без redirect-ите го изхвърляш.

**Извикай:** `security-review` преди пускане. Има плащания, адреси и лични данни.

## 8 · Рискове

1. **myPOS договор** — интеграцията иска реален merchant акаунт. Пиши плъгина срещу sandbox; COD работи независимо, така че сайтът може да тръгне и без картово плащане в краен случай.
2. **Спиди/Еконт креденшъли** — офис списъците са публични, товарителниците не са.
3. **Cloudflare** — ако скрейпването се окаже невъзможно, алтернативата е експорт от клиента. Затова попитай **първо**.
4. **SuperHosting споделен план** — ако клиентът купи споделен вместо VPS, Medusa worker-ът няма да върви стабилно. Уточни преди покупката.
5. **Цени в JSON-LD** — ненадеждни. Не мигрирай цени без клиентът да ги е прегледал.
